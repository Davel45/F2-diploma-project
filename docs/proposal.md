# Thesis Proposal: Відмовостійка платформа онлайн-запису до клінік та телемедицини

## 1. Базова інформація
* **Робоча назва (UKR):** Проєктування та розробка відмовостійкої платформи телемедицини та диспетчеризації записів із механізмом апаратного запобігання овербукінгу
* **Title (ENG):** Design and Implementation of a Fault-Tolerant Telemedicine and Scheduling Platform with Hardware-Level Overbooking Prevention
* **Спеціальність:** F2 Інженерія програмного забезпечення

## 2. Актуальність та проблематика
При масштабуванні медичних інформаційних систем виникає критична проблема узгодженості даних під час одночасного бронювання обмежених тайм-слотів кількома користувачами. Перевірка зайнятості слотів виключно на рівні бізнес-логіки застосунку призводить до стану гонитви (Race Conditions) та виникнення овербукінгу (подвійного запису на один час).

Додатковими викликами є безпечне зберігання чутливих медичних даних (EMR) з дотриманням нормативів конфіденційності, а також ефективна диспетчеризація черг очікування (Waitlist) без виснаження пулу підключень бази даних.

## 3. Сформована ідея продукту
Модульний моноліт (Modular Monolith) на базі Clean Architecture / DDD, що надає функціонал телемедичних консультацій, керування розкладом лікарів та прозорого шифрування медичних карт. Захист від овербукінгу реалізується комбінацією розподілених локів на рівні кешу та апаратних обмежень виключення діапазонів часу на рівні реляційної СУБД.

## 4. Ключовий функціонал (Core Features)
1. **Інтелектуальна фільтрація та каталог спеціалістів:** Пошук фахівців за напрямами, категоріями та найближчими відкритими вікнами прийому з індексацією розкладу.
2. **Захист від овербукінгу (подвійного бронювання):** Розв'язання проблеми стану гонитви (Race Condition) при одночасному бронюванні одного часу кількома пацієнтами.
3. **Дворівневе атомарне бронювання:** Тимчасовий холд слота на 10 хвилин через блокування в Redis та фінальна фіксація в PostgreSQL під контролем Exclusion Constraints (tstzrange).
4. **Забезпечення відмовостійкості (Fault Tolerance):** Асинхронна обробка завдань через брокер черг RabbitMQ; ізоляція збоїв зовнішніх сервісів за патернами Retry та Dead Letter Queue.
5. **Динамічна черга очікування (Waitlist Engine):** Автоматичне вивільнення слотів і сповіщення наступних у черзі пацієнтів через черги повідомлень.
6. **Криптографічний захист медичних записів (EMR Vault):** Прозоре симетричне шифрування діагнозів та призначень на рівні полів таблиць за стандартом AES-256-GCM.
7. **Генерація верифікованих цифрових рецептів:** Створення захищених електронних призначень із генерацією контрольного хешу цілісності SHA-256 та експортом у PDF.
8. **Мультиплексна система сповіщень:** Відкладені push/email нагадування пацієнтам за добу та за 2 години до призначеного візиту через черги повідомлень.
9. **Аналітична панель утилізації робочого часу:** Розрахунок метрик ефективності роботи лікарів, середнього часу прийому та відсотка неявок (No-Show).

## 5. Технологічний стек
* **Мови програмування:** Java 21 (Virtual Threads).
* **Архітектурні патерни:** Modular Monolith, Domain-Driven Design (DDD), Clean Architecture, Transactional Outbox.
* **Бекенд та фреймворки:** Spring Boot 3.3+, Spring Security 6 (JWT / RBAC), Spring Data JPA, Hibernate 6.
* **Бази даних та сховища:** PostgreSQL 16+ (тип даних tstzrange, розширення btree_gist, EXCLUSION CONSTRAINT), Flyway.
* **Асинхронний шар та кеш:** Redis 7 (Redisson Distributed Lock), RabbitMQ.
* **Клієнтський інтерфейс:** Vue 3 (Composition API, Pinia, Tailwind CSS).
* **DevOps та інженерія якості:** Docker, Docker Compose, Testcontainers, SonarQube, GitHub Actions.
