# ВСТУП

## Актуальність теми
При масштабуванні медичних інформаційних систем (МІС) та платформ телемедицини критичним інженерним викликом є забезпечення суворої узгодженості даних (Data Consistency) та мінімізації затримок (Latency) в умовах високонавантаженого конкурентного доступу до обмежених часових ресурсів (слотів прийому). Обробка бронювання виключно на рівні бізнес-логіки застосунку в умовах асинхронного навантаження створює ризики виникнення стану гонитви (Race Conditions), що призводить до овербукінгу (колізії подвійного бронювання) та деградації пропускної здатності реляційної СУБД через надлишкові блокування транзакцій. Водночас зростають вимоги до відмовостійкості (Fault Tolerance) розподілених черг очікування (Waitlist) та наскрізного криптографічного захисту електронних медичних карт (EMR) від компрометації.

Вирішення зазначених проблем вимагає застосування сучасного інженерного підходу: поєднання архітектурного патерну модульного моноліта (Modular Monolith / DDD) із дворівневим механізмом запобігання колізіям на базі розподіленого кешування (Redis/Redisson) та апаратних обмежень виключення на рівні ядра СУБД (PostgreSQL Exclusion Constraints із діапазонами tstzrange). Використання Java 21 з віртуальними потоками (Virtual Threads) та брокера повідомлень RabbitMQ забезпечує високу пропускну здатність, надійну ізоляцію відмов за патерном Dead Letter Queue та гарантоване виконання вимог нормативів захисту конфіденційних медичних даних з використанням алгоритмів AES-256-GCM.

## Об'єкт дослідження
Процес диспетчеризації конкурентних потоків даних онлайн-запису, управління розкладом та синхронізації електронних медичних карт у телемедичних інформаційних системах.

## Предмет дослідження
Методи та алгоритми запобігання колізіям конкурентного доступу (Exclusion Constraints, розподілені блокування), архітектурні патерни модульного моноліта (DDD, Clean Architecture, Transactional Outbox) та технології криптографічного захисту даних (AES-256-GCM) на базі стеку Java 21, Spring Boot, PostgreSQL, Redis та RabbitMQ.

## Мета дослідження
Проєктування та розробка відмовостійкої платформи телемедицини та диспетчеризації записів із механізмом апаратного запобігання овербукінгу для підвищення надійності, ліквідації стану гонитви при конкурентному бронюванні слотів, зниження затримок обробки запитів та гарантування цілісності й конфіденційності медичних даних.

## Завдання проєкту
1. Проаналізувати предметну область, існуючі аналоги медичних систем диспетчеризації та нормативні вимоги ДСТУ/HIPAA для формування технічного завдання.
2. Обґрунтувати вибір технологічного стеку (Java 21, Spring Boot 3, PostgreSQL, Redis, RabbitMQ, Vue 3) за критеріями відмовостійкості, продуктивності та надійності.
3. Спроєктувати модульну архітектуру системи (DDD / Clean Architecture) із побудовою діаграм C4 Model, UML-діаграм прецедентів, послідовності та реляційної схеми даних.
4. Розробити алгоритми та механізми дворівневого запобігання овербукінгу на основі розподілених блокувань Redis та обмежень PostgreSQL (Exclusion Constraints на діапазонах tstzrange), а також логіку динамічної черги очікування (Waitlist Engine).
5. Спроєктувати схеми безпеки, наскрізного симетричного шифрування медичних карт (AES-256-GCM), інтерфейс користувача на базі Vue 3 та інфраструктурну конфігурацію контейнеризації (Docker Compose).
6. Провести інструментальний аудит коду, інтеграційне тестування критичних вузлів конкурентного доступу із застосуванням Testcontainers та статичний аналіз якості у SonarQube.
7. Здійснити науково-практичну апробацію отриманих інженерних рішень шляхом підготовки наукової публікації та проходження нормоконтролю кваліфікаційної роботи.
